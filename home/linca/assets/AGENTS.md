这是一台使用 Nix 配置的机器。如果有缺失的工具，可选的可以使用 `nix run
nixpkgs#工具名` 运行，但请评估该工具的大小，以防下载太大的工具包。

## 需要记住的事情

- **严禁** 对 /nix/store 整个目录进行 `grep` 或 `rg`，这个目录**非常大**，会消耗
  大量的时间。

- **严禁** 对用户目录的 `.config/` `.local/state` `.local/store` 这样的目录进行
  rg 和 grep，防止意外读到敏感的密钥内容。**严禁** 直接读取可能存在机密的文件，
  包括 `.ssh` 下的私钥、sops 文件、age `keys.txt`、命令行 history 等等。如果在读
  取文件的时候发现了密钥、密码、key等内容，立即放下手头的工作，无论是什么，第一
  时间向用户汇报意外读取了什么文件，看到了什么密码，由用户裁定是否需要更换泄露的
  key。

  对于需要密码完成的操作，应提示用户把密码放在 env 文件里，或者放在
  json/toml/yaml 等格式的配置文件里，在不暴露密码的情况下完成操作。

- 用户询问能不能做到某件事的时候，期待的是你回复能或不能，而不是真正行动。任何涉
  及到以用户身份做的事情，应当得到用户授权后再行动。包括：任何平台的登录、push
  github，等等。

- 在用户没有明确要求的情况下，你不可以用 `sudo` `run0` 这样的提权工具。机器上的
  `sudo` 和 `run0` 都被配置为需要密码。如果有需要特权做的事情，明确向用户提出你
  要做什么，为什么，征得同意以后，使用 `run0` 提权。

- 该系统已经配置了使用更现代的 CLI 工具，包括 `fd`, `fzf`, `rg`, `eza`, `bat`,
  `nushell` 等。可选地，可以使用这些现代化的 CLI 工具来完成各种搜索、替换等需
  求。用户更喜欢你使用 javascript 而不是 python 来完成稍复杂的任务。

  `rg` 默认是递归搜索的，无需 `-r`。`rg -rn xxx` 的意思是把出现的 `xxx` 替换成
  `n`，这个错误之前的 AGENT 已经犯过很多次。

- 一个任务的 timeout 应该适当，用户不希望你直接运行需要运行超过 15 秒的命令。如
  果命令超时，第一反应应当是你是否有做错了，而不是放宽时间。编写脚本的时候注意时
  间复杂度，复杂的正则匹配可能产生指数时间的复杂度。对于超过 15 秒的命令，都应该
  先解释一下这个命令为什么可能超过 15 秒。

  特别的，对于网络请求，可以超过 15 秒，但不得超过 60 秒，否则应当先询问用户。
